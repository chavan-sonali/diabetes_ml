DiaMetric — Project Specification

A Clinical Decision Support System (CDSS) for Type 2 Diabetes Mellitus risk stratification, continuous glucose dynamics simulation, and multivariate machine learning analysis.

Domain: Clinical Machine Learning / Endocrinology
Frontend: React 19 + TypeScript + Vite + Tailwind CSS
Primary ML Algorithm: RBF Support Vector Machine (81.17% Acc)
Dataset: Pima & CDC Clinical Cohort (818 Observations)

1. Project Overview & Clinical Objectives

DiaMetric is an interactive Clinical Decision Support System engineered to assess patient susceptibility to Type 2 Diabetes Mellitus (T2DM) and Impaired Fasting Glucose (Pre-Diabetes).

By analyzing non-invasive anthropometric, metabolic, and genetic biomarkers (Plasma Glucose, Glycated Hemoglobin HbA1c, Body Mass Index, Insulin, Age, Diabetes Pedigree Function, Blood Pressure, Pregnancies, Skinfold Thickness), DiaMetric classifies risk severity, projects 24-hour diurnal glucose dynamics, estimates Time-In-Range (TIR 70–180 mg/dL), and synthesizes multi-model consensus across 4 supervised algorithms.

2. Machine Learning Algorithms & Mathematical Foundations

The predictive engine evaluates 4 distinct supervised classifiers trained and benchmarked on standardized diabetes diagnostic cohorts:

Support Vector Machine (RBF) Primary • 81.17% Acc

Radial Basis Function (RBF) kernel mapping non-linearly separable metabolic markers into high-dimensional Hilbert space. Maximizes the margin separating normoglycemic and diabetic hyperplanes.

K(x, x') = exp(-γ ||x - x'||²)
Random Forest (100 Trees) Ensemble • 79.87% Acc

Bootstrap aggregation (Bagging) ensemble over 100 orthogonal decision trees. Ranks feature importance via Gini Impurity reduction; resists overfitting on noisy physiological features.

Gini(p) = 1 - ∑ (p_i)²
AdaBoost Classifier Boosting • 77.27% Acc

Adaptive boosting sequential ensemble that iteratively re-weights misclassified borderline samples (e.g. pre-diabetic borderline glucose 100–125 mg/dL) to sharpen classification boundaries.

H(x) = sign(∑ α_t · h_t(x))
Decision Tree (CART) White-Box • 74.03% Acc

Classification and Regression Tree performing greedy binary splits on dominant thresholds: Glucose ≥ 127 mg/dL, BMI ≥ 29.8 kg/m², Age ≥ 30 yrs. Highly interpretable for clinical validation.

Split = argmin [ (N_L/N)·G_L + (N_R/N)·G_R ]

Principal Component Analysis (PCA)

Unsupervised orthogonal transformation compressing the 9-dimensional clinical space into 2 principal components, retaining 46.80% of total cohort variance (PC1: 31.2%, PC2: 15.6%). PC1 captures the primary Glycemic-Adiposity axis separating healthy and diabetic phenotypes.

3. Frontend Architecture & Technology Stack

The client interface is engineered as a responsive Single Page Application (SPA) prioritizing clinical legibility, high contrast, and responsive interactivity:

  • React 19 & TypeScript: Component-driven architecture with strict type checking (strict TypeScript interfaces for PatientInputs, PredictionResult, ClinicalAxisScore).
  • Vite Build Tool: Modern ES module bundler providing zero-bundle startup, sub-second Hot Module Replacement, and optimized production builds.
  • Tailwind CSS v4 & Pink/Obsidian Theme: High-tech clinical design system utilizing obsidian backgrounds (#070B14, #0D1322) paired with rose/pink clinical accents (#F43F5E, #E11D48, #FB7185) and light/dark theme persistence.
  • Chart.js & React-ChartJS-2: Hardware-accelerated canvas charts for model benchmark comparisons and the 5-Axis Spider Radar Chart.
  • HTML5 Canvas Diurnal Glucose Engine: Custom 60fps canvas simulation calculating 24-hour continuous glucose waveforms, postprandial glycemic spikes, dawn phenomenon, and Time-In-Range (TIR) metrics.
  • Lucide Icons: Consistent, accessible SVG iconography.

4. Python Backend Architecture & REST API Pipeline

The backend engine is engineered in Python 3 utilizing standard machine learning pipelines (scikit-learn, pandas, numpy, Flask) and seamlessly bridged to the full-stack container:

  • Python Standalone REST API Server (backend/app.py): A high-performance Python REST API server implementing standard clinical routes:
    POST /api/predict -> Runs Python RBF-SVM & Multi-Model Inference GET /api/models -> Returns Scikit-Learn Confusion Matrices & Benchmarks GET /api/health -> Returns Python 3.10 runtime & ML engine diagnostics
  • Python Scikit-Learn Training Pipeline (ml/train_models.py): Standardized Python training script performing stratified 80/20 train/test splitting, cross-validation, hyperparameter tuning for RBF-SVM ($C=1.5, \gamma=\text{'scale'}$), Random Forest (100 trees), AdaBoost, and CART, generating ml/saved_models/metrics.json.
  • Python Vectorized Inference Module (ml/predict.py): Accepts patient JSON telemetry via CLI/IPC or direct Python function call, computes exact StandardScaler z-scores, RBF kernel logits, ADA diagnostic staging, and 5-axis clinical radar metrics.
  • Python Requirements & Environment (requirements.txt): Contains complete dependencies: scikit-learn>=1.3.0, pandas>=2.0.0, numpy>=1.24.0, Flask>=3.0.0, gunicorn>=21.2.0.
  • Zero-Food Clinical Recommendation Engine: Delivers non-pharmacological physical activity protocols (Zone 1-2 aerobic training, insulin-sensitizing resistance regimens, postprandial walks) and contraindication safety alerts strictly omitting food suggestions.
